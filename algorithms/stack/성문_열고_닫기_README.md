# 성문 열고 닫기

## 문제 설명

`<`는 성문이 열리는 것, `>`는 성문이 닫히는 것을 의미한다.
주어진 문자열이 올바르게 열리고 닫히는지 확인하라.

**올바른 예시:** `<<>>`, `<>`  
**잘못된 예시:** `>><<`, `<<<>`

---

## 접근 방식

### 자료구조: 스택 (Stack)

- **왜 이 자료구조인가?**: 성문은 "가장 마지막에 열린 것이 가장 먼저 닫혀야" 하는 LIFO 구조다. `<`를 열 때 스택에 쌓고 `>`를 만날 때 스택에서 꺼내면 자연스럽게 짝 검증이 된다.
- **핵심 패턴**: 괄호/짝 맞추기 문제의 전형적인 패턴. 여는 기호 → push, 닫는 기호 → pop. 닫는 기호 도달 시 스택이 비어있으면 Invalid.
- **풀기 전 체크리스트**:
  - 추적해야 할 상태: 아직 닫히지 않은 열린 성문의 수
  - 입력: 문자열 (`<`, `>`로만 구성), 출력: boolean
  - 엣지케이스: 빈 문자열, `>`로 시작하는 경우, 열기만 하고 안 닫는 경우
- **일반적인 접근 순서**:
  1. 문자열을 왼쪽부터 순회
  2. `<` → 스택에 push (열린 상태 기록)
  3. `>` → 스택이 비어있으면 즉시 `false` 반환, 아니면 pop
  4. 순회 후 스택이 비어있으면 `true`, 남아있으면 `false`

---

## 내 풀이

```js
function solution(gate) {
  const stack = [];

  for (const char of gate) {
    if (char === "<") {
      stack.push(char);
    } else {
      if (stack.length === 0) {
        return false;
      }
      stack.pop();
    }
  }

  return stack.length === 0;
}
```

### 풀이 과정

1. `<`를 만나면 스택에 push
2. `>`를 만났을 때 스택이 비어있으면 닫을 문이 없으므로 `false` 반환
3. 스택이 비어있지 않으면 pop (열린 문을 닫음)
4. 반복문이 끝난 후 스택이 비어있으면 `true`, 아니면 `false`

**시간복잡도:** O(n) — 문자열을 한 번 순회  
**공간복잡도:** O(n) — 최대 n/2개의 요소가 스택에 쌓임

## Claude 풀이

```js
function solutionByClaude(gate) {
  let openCount = 0;

  for (const char of gate) {
    if (char === "<") {
      openCount++;
    } else {
      if (openCount === 0) return false;
      openCount--;
    }
  }

  return openCount === 0;
}
```

### 설명

이 문제는 여는/닫는 기호가 `<` 하나뿐이므로 실제 스택 자료구조 대신 **카운터**로 대체할 수 있다.
열린 수를 정수로 추적하면 메모리를 O(1)로 줄일 수 있다.

- 스택에 실제로 값을 저장할 필요 없이 "열린 개수"만 알면 충분
- 코드가 더 단순하고 메모리 효율적

**시간복잡도:** O(n)  
**공간복잡도:** O(1) ← 내 풀이보다 개선

## 두 풀이 최종 비교

| 항목 | 내 풀이 | Claude 풀이 |
|------|---------|-------------|
| 핵심 자료구조 | Stack (배열) | 정수 카운터 |
| 공간복잡도 | O(n) | O(1) |
| 시간복잡도 | O(n) | O(n) |
| 확장성 | 여러 종류의 괄호 문제에 그대로 적용 가능 | 이 문제처럼 단일 괄호 쌍에만 적합 |

> **포인트:** 괄호 종류가 여러 개라면 (`[]{}()`) 내 풀이처럼 스택을 써야 한다. 이 문제처럼 종류가 하나라면 카운터가 더 간결하다.
