# 뒤집은 소수

## 문제 설명

정수 배열이 주어질 때, 각 정수의 자리수를 뒤집은 수가 소수인 경우 그 뒤집은 수를 모아 배열로 반환하라.

**예시:**
- 입력: `[32, 55, 62, 20, 250, 370, 200, 30, 100]`
- 각 수를 뒤집으면: 23, 55, 26, 2, 52, 73, 2, 3, 1
- 이 중 소수: **23, 2, 73, 2, 3**
- 출력: `[23, 2, 73, 2, 3]`

---

## 접근 방식

### 알고리즘: 완전탐색 (브루트포스)

- **왜 이 방식인가?**: 모든 원소에 대해 자리수 뒤집기와 소수 판별을 순서대로 수행해야 한다. 최적화 없이 각 원소를 직접 확인하는 완전탐색이 자연스러운 접근이다.
- **핵심 패턴**: 숫자 변환(뒤집기) + 소수 판별을 조합한 "변환 후 조건 필터링" 패턴
- **풀기 전 체크리스트**:
  - 추적할 상태: 뒤집은 수(`res`), 소수 여부
  - 입력: 정수 배열 / 출력: 뒤집었을 때 소수인 수들의 배열
  - 엣지케이스: 1은 소수가 아님, 앞 자리가 0인 경우(예: 20 → 02 = 2)
- **일반적인 접근 순서**:
  1. 배열을 순회
  2. 각 원소의 자리수를 뒤집어 새 숫자 생성
  3. 뒤집은 숫자가 소수인지 판별
  4. 소수이면 결과 배열에 추가

---

## 내 풀이

```js
function solution(array) {
  let answer = [];

  for (let x of array) {
    let res = 0;

    while (x) {
      let t = x % 10;
      res = res * 10 + t;

      x = parseInt(x / 10);
    }

    if (isPrime(res)) {
      answer.push(res);
    }
  }

  return answer;
}

function isPrime(num) {
  if (num === 1) return false;

  for (let i = 2; i < num / 2; i++) {
    if (num % i === 0) return false;
  }

  return true;
}

console.log(solution([32, 55, 62, 20, 250, 370, 200, 30, 100]));
```

### 풀이 과정

1. 각 원소 `x`에 대해 `res = res * 10 + (x % 10)` 반복으로 자리수를 뒤집음
2. `isPrime`으로 소수 판별: 1은 제외, 2부터 `num/2` 미만까지 나누어 떨어지면 비소수
3. 소수면 `answer`에 추가 후 반환

> **참고:** `isPrime`에서 `i < num / 2` 조건은 num=4일 때 4를 소수로 잘못 판정하는 버그가 있다. 이 테스트케이스에서는 뒤집힌 수 중 4가 없어 통과되지만, 정확한 판별은 `i <= Math.sqrt(num)` 또는 `i * i <= num`을 사용해야 한다.

- **시간복잡도**: O(n × (d + m)) — n: 배열 길이, d: 자리수, m: 뒤집은 수의 크기
- **공간복잡도**: O(n)

## Claude 풀이

```js
function solution(array) {
  const isPrime = n => {
    if (n < 2) return false;
    for (let i = 2; i * i <= n; i++) {
      if (n % i === 0) return false;
    }
    return true;
  };

  return array
    .map(x => Number(String(x).split('').reverse().join('')))
    .filter(isPrime);
}

console.log(solution([32, 55, 62, 20, 250, 370, 200, 30, 100]));
```

### 설명

- 문자열 변환 + `reverse()` + `join('')`으로 자리수 뒤집기를 선언적으로 처리
- `isPrime`은 `i * i <= n` 조건 사용 → 시간복잡도 O(√n)으로 정확하고 효율적
- `map` → `filter` 파이프라인으로 변환과 필터링을 분리해 가독성 향상
- **장점**: 간결하고 버그 없는 소수 판별, 함수형 스타일
- **단점**: `String()` + `split` + `reverse` + `join`의 연산 비용이 while 방식보다 약간 큼

---

## 두 풀이 최종 비교

| 항목 | 내 풀이 | Claude 풀이 |
|------|---------|-------------|
| 자리수 뒤집기 방식 | while + 나머지 연산 | 문자열 변환 + reverse |
| 소수 판별 범위 | `i < num / 2` (버그 있음) | `i * i <= n` (정확) |
| 코드 간결성 | 보통 | 높음 |
| 가독성 | 절차적, 명시적 | 선언적, 파이프라인 |
| 시간복잡도 (소수 판별) | O(n) | O(√n) |
| 공간복잡도 | O(n) | O(n) |

### 핵심 차이점

가장 중요한 차이는 **소수 판별 정확성**이다. 내 풀이의 `i < num / 2` 조건은 num=4 등 일부 합성수를 소수로 잘못 판별하는 버그가 있다. Claude 풀이는 `i * i <= n`으로 이를 수정하고, 시간복잡도도 O(√n)으로 개선한다. 자리수 뒤집기는 두 방식 모두 유효하나 while 방식이 공간 효율이 약간 더 좋다.
