# 두 배열 합치기

## 문제 설명

두 개의 오름차순 정렬된 배열이 주어질 때, 두 배열을 합쳐 하나의 오름차순 정렬된 배열로 반환하라.

**예시:**
- 입력: `arr1 = [1, 3, 5]`, `arr2 = [2, 3, 6, 7, 9]`
- 출력: `[1, 2, 3, 3, 5, 6, 7, 9]`

---

## 접근 방식

### 알고리즘: 투 포인터 (Two Pointer)

- **왜 이 방식인가?**: 두 배열이 이미 정렬되어 있으므로, 각 배열의 앞에서부터 포인터를 하나씩 두고 작은 값을 순서대로 선택하면 전체를 다시 정렬하지 않고 O(n+m)에 병합이 가능하다. 이는 병합 정렬(Merge Sort)의 핵심 단계이기도 하다.
- **핵심 패턴**: 두 정렬 배열의 병합 패턴. 두 포인터를 앞에서 시작해 더 작은 값을 결과 배열에 추가하고 해당 포인터를 전진시킨다. 한 배열이 소진되면 나머지 배열의 남은 원소를 모두 이어붙인다.
- **풀기 전 체크리스트**:
  - 추적할 상태: `p1` (arr1 포인터), `p2` (arr2 포인터), 결과 배열
  - 입력: 정렬된 두 정수 배열 / 출력: 병합된 정렬 배열
  - 엣지케이스: 한쪽 배열이 빈 경우, 두 배열의 길이가 다른 경우, 중복 원소 존재
- **일반적인 접근 순서**:
  1. 두 포인터를 각 배열의 0번 인덱스에 위치
  2. 두 포인터가 모두 범위 내일 때, 작은 값을 결과에 추가하고 해당 포인터 전진
  3. 한쪽 배열이 소진되면 나머지 배열의 남은 원소를 모두 추가
  4. 결과 배열 반환

---

## 내 풀이

```js
function solution(arr1, arr2) {
  const answer = [];
  const n = arr1.length;
  const m = arr2.length;
  let p1 = 0;
  let p2 = 0;

  while (p1 < n && p2 < m) {
    if (arr1[p1] < arr2[p2]) {
      answer.push(arr1[p1++]);
    } else {
      answer.push(arr2[p2++]);
    }
  }

  while (p1 < n) {
    answer.push(arr1[p1++]);
  }

  while (p2 < m) {
    answer.push(arr2[p2++]);
  }

  return answer;
}

console.log(solution([1, 3, 5], [2, 3, 6, 7, 9]));
```

### 풀이 과정

1. `p1`, `p2`를 각 배열의 시작점으로 초기화
2. 두 포인터가 모두 범위 내일 때: `arr1[p1] < arr2[p2]`이면 arr1 원소 추가 후 p1 전진, 아니면 arr2 원소 추가 후 p2 전진 (같을 때는 arr2 원소가 먼저 추가됨)
3. arr1이 남으면 나머지 모두 추가, arr2가 남으면 나머지 모두 추가

- **시간복잡도**: O(n + m) — 두 배열을 각 한 번씩 순회
- **공간복잡도**: O(n + m) — 결과 배열 크기

## Claude 풀이

기존 내 풀이가 투 포인터 병합의 정석 구현이다. 더 나은 접근법이 없으므로 내 풀이를 최선으로 선택한다.

```js
function solution(arr1, arr2) {
  const answer = [];
  const n = arr1.length;
  const m = arr2.length;
  let p1 = 0;
  let p2 = 0;

  while (p1 < n && p2 < m) {
    if (arr1[p1] < arr2[p2]) {
      answer.push(arr1[p1++]);
    } else {
      answer.push(arr2[p2++]);
    }
  }

  while (p1 < n) {
    answer.push(arr1[p1++]);
  }

  while (p2 < m) {
    answer.push(arr2[p2++]);
  }

  return answer;
}
```

### 설명

투 포인터 병합은 이미 최적 알고리즘이다 (O(n+m)). 대안으로 `[...arr1, ...arr2].sort((a,b) => a-b)`도 가능하지만, 이는 O((n+m) log(n+m))으로 더 느리고 두 배열이 정렬되어 있다는 조건을 활용하지 못한다.

---

## 두 풀이 최종 비교

| 항목 | 내 풀이 (= Claude 풀이) | spread + sort 대안 |
|------|------------------------|-------------------|
| 핵심 아이디어 | 투 포인터 병합 | 합치고 재정렬 |
| 시간복잡도 | O(n + m) | O((n+m) log(n+m)) |
| 정렬 조건 활용 | 활용 | 미활용 |
| 코드 길이 | 길지만 명확 | 짧지만 비효율 |

### 핵심 차이점

두 배열이 이미 정렬되어 있다는 선행 조건을 투 포인터로 활용하면 O(n+m)에 병합이 가능하다. 이 조건을 무시하고 재정렬하면 O((n+m) log(n+m))이 소요되므로, 투 포인터 방식이 이 문제의 최선이다.
