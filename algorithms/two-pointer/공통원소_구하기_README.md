# 공통원소 구하기

## 문제 설명

두 개의 정수 배열이 주어질 때, 두 배열에 공통으로 존재하는 원소들을 오름차순으로 반환하라.

**예시:**
- 입력: `arr1 = [1, 3, 9, 5, 2]`, `arr2 = [3, 2, 5, 7, 8]`
- 정렬 후: `[1, 2, 3, 5, 9]`, `[2, 3, 5, 7, 8]`
- 공통 원소: **2, 3, 5**
- 출력: `[2, 3, 5]`

---

## 접근 방식

### 알고리즘: 투 포인터 (Two Pointer)

- **왜 이 방식인가?**: 두 배열을 정렬한 뒤 포인터를 앞에서 이동시키면, 작은 쪽 포인터를 전진시키는 방식으로 중복 없이 공통 원소를 O(n+m)에 추출할 수 있다. 집합 교집합 연산의 효율적인 구현이다.
- **핵심 패턴**: 정렬 후 동시 순회 패턴. 두 포인터의 값을 비교해 같으면 결과에 추가, 다르면 작은 쪽 포인터를 전진시킨다.
- **풀기 전 체크리스트**:
  - 추적할 상태: `p1` (arr1 포인터), `p2` (arr2 포인터), 공통 원소 배열
  - 입력: 두 정수 배열 (정렬 불필요) / 출력: 공통 원소의 오름차순 배열
  - 엣지케이스: 공통 원소가 없는 경우, 중복된 값이 있는 경우
- **일반적인 접근 순서**:
  1. 두 배열 모두 오름차순 정렬
  2. 두 포인터를 0번 인덱스에서 시작
  3. `arr1[p1] === arr2[p2]`이면 결과에 추가하고 둘 다 전진
  4. 작은 쪽 포인터를 전진 (큰 값을 따라잡기 위해)
  5. 결과 반환

---

## 내 풀이

```js
function solution(arr1, arr2) {
  arr1.sort((a, b) => a - b);
  arr2.sort((a, b) => a - b);

  const answer = [];
  const n = arr1.length;
  const m = arr2.length;

  let p1 = 0;
  let p2 = 0;

  while (p1 < n && p2 < m) {
    if (arr1[p1] < arr2[p2]) {
      p1++;
    } else if (arr1[p1] > arr2[p2]) {
      p2++;
    } else {
      answer.push(arr1[p1]);
      p1++;
      p2++;
    }
  }

  return answer;
}

console.log(solution([1, 3, 9, 5, 2], [3, 2, 5, 7, 8]));
```

### 풀이 과정

1. 두 배열을 오름차순 정렬
2. 두 포인터가 모두 범위 내일 때:
   - `arr1[p1] < arr2[p2]`: arr1이 더 작으므로 p1 전진 (arr1이 arr2를 따라잡도록)
   - `arr1[p1] > arr2[p2]`: arr2가 더 작으므로 p2 전진
   - `arr1[p1] === arr2[p2]`: 공통 원소, 결과에 추가 후 둘 다 전진
3. 한쪽이 소진되면 종료

- **시간복잡도**: O(n log n + m log m) — 정렬 비용이 지배
- **공간복잡도**: O(k) — k는 공통 원소 수

## Claude 풀이

기존 내 풀이가 투 포인터 교집합의 정석 구현이다. 더 나은 접근법이 없으므로 내 풀이를 최선으로 선택한다.

```js
function solution(arr1, arr2) {
  arr1.sort((a, b) => a - b);
  arr2.sort((a, b) => a - b);

  const answer = [];
  const n = arr1.length;
  const m = arr2.length;

  let p1 = 0;
  let p2 = 0;

  while (p1 < n && p2 < m) {
    if (arr1[p1] < arr2[p2]) {
      p1++;
    } else if (arr1[p1] > arr2[p2]) {
      p2++;
    } else {
      answer.push(arr1[p1]);
      p1++;
      p2++;
    }
  }

  return answer;
}
```

### 설명

대안으로 Set을 활용한 방법도 가능하다:
```js
const set = new Set(arr1);
return arr2.filter(x => set.has(x)).sort((a, b) => a - b);
```
이는 O(n + m) 탐색이지만 Set 생성과 sort가 추가된다. 투 포인터 방식은 정렬 비용을 공유할 수 있고, 결과가 자동으로 정렬된 상태로 나온다는 장점이 있다.

---

## 두 풀이 최종 비교

| 항목 | 내 풀이 (= Claude 풀이) | Set 활용 대안 |
|------|------------------------|--------------|
| 핵심 아이디어 | 정렬 후 투 포인터 | Set으로 O(1) 조회 |
| 시간복잡도 | O(n log n + m log m) | O(n + m log m) |
| 공간복잡도 | O(k) | O(n) — Set 크기 |
| 결과 정렬 | 자동 (정렬된 순서 유지) | 별도 sort 필요 |
| 코드 간결성 | 보통 | 높음 |

### 핵심 차이점

투 포인터는 정렬 비용이 있지만 결과가 자연스럽게 오름차순으로 나온다. Set 방식은 O(1) 탐색으로 빠르지만, 결과를 정렬하는 추가 비용이 필요하다. 두 방식 모두 유효하며, 입력 배열 크기에 따라 선택이 달라진다.
